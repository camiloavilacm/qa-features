# Central SEED-1 campaign — Step 6

The public qa-features repository hosts campaign.yml. Two jobs build the pinned SUT source commits once, publish private CI images, and expose immutable registry digests/config IDs. Six independent matrix jobs execute three unchanged scenarios through Playwright, Selenium or Cypress against each SUT. fail-fast is disabled. One reporting job runs after the matrix even on failure; it validates and renders the current attempt, archives the JSON/Markdown/provenance/artifacts, and refuses a passing conclusion for incomplete, failed or invalid results.

The workflow dispatch uses public HTTPS source checkouts, package-scoped workflow permissions for images, and separate issue permissions in the reporting job. No source credential is persisted for test code. Action revisions are pinned in action-pins.json; application/runner commits and source fingerprints are pinned in repositories.json. Actual running-container image IDs, OCI source-revision labels, registry digests and checked-out commits are verified before a slot receipt is accepted. Runtime result tooling_ref is the actual workflow source commit.

Campaign ID is stable across full reruns of the same GitHub run; execution IDs and attempt artifacts are fresh. The artifact pattern includes the attempt, so failed-job-only reruns cannot borrow previous results. All six slots are explicit; missing evidence produces incomplete and invalid evidence produces error with no fabricated passing assertion. Invalid copied artifacts are discarded. Existing attempt directories cannot be overwritten. The approved result/campaign schemas and feature tag remain unchanged.

Use tools/campaign/launch.py dispatch|wait|download|rerun --record <external-or-evidence-record.json>. A full rerun uses the same record and `wait --attempt 2`; download to a different directory for every attempt. Commands use gh authentication without reading or printing tokens. The optional workflow report_issue input selects an existing issue in the same private repository, using its built-in reporting token. The configured default is issue 1 in qa-features; setting 0 explicitly renders artifacts/job summary without sending a comment. For an explicitly authorized external sandbox, run tools/campaign/publish.py --directory <downloaded-attempt> --repository camiloavilacm/ai-qa-agent --issue 2 through a trusted operator; source checkout credentials remain separate from that reporting credential. This publishes only the sanitized report, never private artifact contents. There is no implicit cross-repository token access.

The reporting publisher maintains one comment per issue/campaign; a rerun updates the same comment. All attempt artifacts remain archived. Cross-host writers must be serialized; workflow concurrency is grouped by run ID and the operator launch sequence is serial. Observer_fault=unavailable is an explicit development failure-path run affecting sut-python:playwright; it does not alter assertions or provide stub HTTP responses.

Registered development checks are six-jobs, single-report, failure-paths and no-model-calls. Supply QA_STEP6_RUNS_FILE pointing to an external JSON object with normal/rerun/failure absolute archived-attempt directories. Completion requires actual hosted job outcomes and 18 passes on both initial/full rerun, one campaign comment across the rerun, the real unavailable-observer failure campaign, and the deterministic fixture regressions. Signed check logs bind hashes of every archived acceptance file. No parent untracked workspace file is required: runner runtime source inspection reads the pinned private GitHub archives. Nine fixture tests are development checks, not execution evidence. No runtime model client, auto-healing, development-provider probe or agent is invoked by CI.

Source publication/commits are part of the explicitly authorized Step 6 implementation. Reference-only baseline checkpoints retain the original content inventories and require fast-forward changes to the current source branch; tags and other refs cannot change. Original baselines are preserved externally. This is CI integration evidence, not the clean-machine immutable smoke release or rollback of Step 7.
